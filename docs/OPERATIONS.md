# 운영 안내

## 첫 기록

로그인 → 수동 운영 → 상품 등록. SKU에는 용량·색상·수량·지역·보증을 함께 입력합니다. 다른 SKU는 별도 상품입니다. 가격 등록 시 출처명·가격·관측 시각·상태를 입력합니다. 배송비 0원은 확인된 무료배송일 때만 입력하세요. 빈칸은 미확인입니다.

조건·옵션·재고를 확인해야 현재 유효 가격으로 취급합니다. 출시가는 기준 가격이고 현재 구매가가 아닙니다. 현재 가격은 24시간 이내 관측만 사용합니다. 핫딜은 종료시각이 필요합니다. 현재 재고를 보장하지 않습니다.

목표가는 상태별로 저장합니다. 새 가격 입력 시와 1분 간격의 내부 평가에서 알림을 기록합니다. 이는 가격 수집 주기가 아닙니다. 앱 내부 알림만 있고 외부 메시지는 보내지 않습니다.

## CSV

설정에서 양식을 다운로드합니다. UTF-8 CSV, 1MB·1,000행 제한. 통화는 원화만 지원합니다. KST 시각에 시간대가 없으면 +09:00으로 해석합니다. CSV 값은 검증되지 않은 기록으로 저장되므로 현재가 순위에서 제외됩니다. 상품 상세에서 출처를 확인한 최신 관측을 추가하세요. 중복은 제외하고 실패 행을 보여줍니다. 자동 병합은 하지 않습니다.

## 백업 / 복원

`node --env-file-if-exists=.env src/backup.mjs`는 `VACUUM INTO`로 일관된 SQLite 사본을 만듭니다. 기본 저장 위치는 `data/backups/`입니다. 다른 저장 위치를 첫 인자로 지정할 수 있습니다. 백업 파일에는 개인 기록이 들어 있으므로 외부 공유하지 마세요.

복원: 서버 종료 → 기존 DB와 `-wal`, `-shm` 파일을 별도 안전 폴더에 보관 → 백업 사본을 `data/radar.sqlite`로 복사 → 서버 시작 → 다시 로그인하여 상품/규칙/알림 확인. DB 파일 교체는 실행 중에 하지 않습니다. `.env`는 DB와 별도로 보관하세요. JSON 내보내기는 검토용이며 전체 복원 도구가 아닙니다.

## 문제 해결

- 비밀번호 분실: 서버를 멈추고 `node src/password.mjs`로 새 해시를 만든 뒤 `.env`의 `PASSWORD_HASH`를 교체합니다.
- 주소가 열리지 않음: 실행 창이 열려 있는지, 해당 포트가 다른 프로그램에 사용 중인지 확인합니다.
- 관측 최저가가 없음: 재고/일치/검증/배송/회원 조건/24시간 유효성을 확인합니다.
- 데모가 오래됨: 로컬 데모 실행을 종료 후 다시 열면 새 인메모리 예시가 만들어집니다. 운영 DB에 저장된 데모는 자동 갱신되지 않습니다.
- 배포 버전 변경 전: DB 백업 → 코드 업데이트 → 테스트 → 재시작.

현재 schema version은 1입니다. 향후 구조 변경 시 버전별 마이그레이션이 필요합니다. 다중 프로세스/다중 사용자 운용은 지원하지 않습니다.
